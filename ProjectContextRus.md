# PROJECT CONTEXT: HR Hiring System

## 1. Обзор проекта:

Pet-проект "HR Hiring System" для демонстрации системной интеграции.
Frontend/Пользовательский интерфейс состоит из двух форм (Candidate/Кандидат и HR), расположенных в одной вкладке браузера. Переключение между формами выполняется с помощью переключателя режимов.
Backend/Серверная часть отвечает за бизнес-логику API и работу с базой данных.

    Технологии:
        Python 3.x
        FastAPI + SQLAlchemy + Uvicorn
        Streamlit
        SQLite (локальная разработка)/PostgreSQL (production/промышленная среда)
        python-dotenv
        Gmail SMTP (отправка email-уведомлений)

    API_URL/URL API = "http://127.0.0.1:8000"
    API title/Название API = "HR Hiring System API"
    API version/Версия API = "1.1.0"

## 2. Основной процесс:

Candidate/Кандидат отправляет заявку, которую система сохраняет в таблице Applications/Отклики. Заявки отображаются HR-специалисту, который принимает решение: "Принять на работу" или "Отклонить".

    Если "Принять на работу":
        Статус заявки становится "Принят".
        Связанная должность помечается как занятая (is_free/Доступна = False/Ложь).
        Кандидату отправляется email с уведомлением о найме.
        На Support Email/Email службы поддержки отправляется уведомление о необходимости подготовить рабочее место.

    Если "Отклонить":
        Статус заявки становится "Отклонена".
        Запись сохраняется в базе данных для истории (Soft Delete/Мягкое удаление).
        Кандидату отправляется email с уведомлением об отказе.
        Кандидат может повторно подать заявку на ту же должность.

    Обрабатывать можно только заявки со статусом "Новая".
    После перехода в "Принят" или "Отклонена" повторное изменение статуса недоступно.

        Показать сообщение об ошибке отправки данных.

    При других ошибках:
        Показать сообщение об ошибке с кодом HTTP.

## 2. Backend Logic & Database Schema/Логика backend и схема базы данных

Генерация ID: UUID создаётся на стороне backend при создании записей.

Таблица: Positions/Должности

    id/ID          (UUID, Primary Key/Первичный ключ)
    pos_name/Название должности    (String)
    is_free/Доступна     (Boolean, default True/Истина)

Таблица: Applications/Отклики

    id/ID          (UUID, Primary Key/Первичный ключ)
    position_id/ID должности (UUID, Foreign Key/Внешний ключ referencing Positions.id/ссылается на Positions.id.
                 UI/Пользовательский интерфейс отображает pos_name/Название должности, но в базе хранится position_id/ID должности)
    app_date/Дата заявки    (DateTime, дата создания заявки в UTC)
    educ/Образование        (String)
    experience/Опыт работы  (String)
    full_name/ФИО   (String)
    email/Электронная почта       (String, нормализуется: пробелы удаляются, буквы переводятся в нижний регистр)
    birth_date/Дата рождения  (Date)
    status/Статус      (String: "New/Новая", "Hired/Принят", "Canceled/Отклонена")

Ответ API для Applications/Откликов также содержит:

    position_name/Название должности (String, название должности из таблицы Positions/Должности)

## 2.1 Логика endpoint/Конечной точки: POST /api/applications

    Получить данные из JSON-тела запроса.

    Проверить position_id/ID должности:
        Преобразовать UUID в строковое представление.
        Найти соответствующую запись в таблице Positions/Должности.

    Если должность не найдена:
        Вернуть HTTP 404 Not Found/Не найдено: "Position not found."

    Нормализовать email/Электронная почта:
        Удалить пробелы по краям.
        Перевести email в нижний регистр.

    Найти заявку в таблице Applications/Отклики, где:
        email/Электронная почта совпадает с нормализованным email
        AND/И position_id/ID должности совпадает с полученным position_id/ID должности
        AND/И status/Статус равен "New/Новая" OR/ИЛИ "Hired/Принят".

    Если такая заявка найдена:
        Вернуть HTTP 409 Conflict/Конфликт:
        "You have already applied for this position."

    Иначе:
        Создать новую запись в Applications/Откликах:
            - Сгенерировать UUID id/ID.
            - Записать текущую дату и время в app_date/Дата заявки (UTC).
            - Сохранить данные из формы.
            - Сохранить нормализованный email/Адрес электронной почты.
            - Установить status/Статус = "New/Новая".

        Если предыдущая заявка имеет статус "Canceled/Отклонена":
            Сохранить старую запись для истории.
            Создать новую запись с новым UUID.

        Вернуть HTTP 201 Created/Создано.

    Дополнительная обработка:
        При IntegrityError выполнить rollback и вернуть HTTP 409 Conflict/Конфликт.
        При непредвиденной ошибке выполнить rollback и вернуть HTTP 500 Internal Server Error/Внутренняя ошибка сервера.

## 2.3 Логика endpoint/Конечной точки: POST /api/reset-demo

    1. Удалить все существующие записи из таблицы Applications/Отклики.
    2. Удалить все существующие записи из таблицы Positions/Должности.
    3. Создать три demo-должности:
        - Senior Backend Developer
        - Frontend Engineer
        - HR Manager
    4. Создать шесть demo-заявок:
        - Три английских примера.
        - Три русских примера.
    5. Установить is_free/Доступна = False/Ложь для Frontend Engineer, поскольку одна из demo-заявок на эту должность имеет статус "Hired/Принят".
    6. Сохранить изменения в базе данных.
    7. Вернуть HTTP 200 OK с количеством созданных должностей и заявок.
    8. Frontend/Пользовательский интерфейс обновляет интерфейс и отображает сообщение об успешной загрузке demo-данных.

    Важно:
        Endpoint/Конечная точка удаляет и пересоздаёт должности, а не только сбрасывает их доступность.
        Существующие заявки и должности удаляются при сбросе demo-данных.

## 2.4 Реализованные API endpoints/Конечные точки API

    GET /api/positions
        Возвращает список должностей с полями id/ID, pos_name/Название должности, is_free/Доступна.

    POST /api/positions
        Создаёт новую должность.
        Принимает JSON с pos_name/Название должности и is_free/Доступна.
        Возвращает HTTP 201 Created/Создано.

    GET /api/applications
        Возвращает список заявок вместе с position_name/Название должности.
        Поддерживает необязательные параметры:
            position/Должность  (поиск по названию должности, частичное совпадение)
            full_name/ФИО (поиск по ФИО, частичное совпадение)

        Фильтрация по email/Электронная почта выполняется на frontend/Пользовательском интерфейсе.

    POST /api/applications
        Создаёт заявку с проверкой обязательных полей и дубликатов.

    PATCH /api/applications/{app_id}/status
        Изменяет статус заявки на "Hired/Принят" или "Canceled/Отклонена".
        Обрабатывает только заявки со статусом "New/Новая".
        При найме делает связанную должность недоступной.
        Пытается отправить email кандидату и, при найме, службе поддержки.
        Возвращает информацию о статусе и результатах отправки email.

    PATCH /api/applications/{app_id}/email
        Обновляет email/Электронную почту существующей заявки.
        Удаляет пробелы по краям и переводит email в нижний регистр.
        Проверяет наличие символа "@".
        Возвращает HTTP 404, если заявка не найдена.
        Возвращает HTTP 422 при некорректном email.
        При IntegrityError возвращает HTTP 409 Conflict/Конфликт.

    POST /api/reset-demo
        Удаляет и пересоздаёт demo-должности и demo-заявки.

    GET /api/demo-application?lang=en|ru
        Возвращает первый demo-пример для выбранного языка.
        Поддерживаемые значения lang/Язык: "en" и "ru".
        Если язык не поддерживается, возвращает HTTP 400 Bad Request/Некорректный запрос.

## 3.4 Логика выбора строки и действий

    Если пользователь выбрал одну заявку:
        Проверить статус заявки.
        Проверить корректность email.
        Проверить наличие конфликта email.
        Если статус = "New/Новая", email корректен и конфликта нет:
            Разрешить действия Hire/Принять на работу и Reject/Отклонить.

    Если пользователь не выбрал ни одной заявки:
        Показать подсказку "Select one application."/"Выберите одну заявку."
        Отключить Hire/Принять на работу и Reject/Отклонить.

    Если пользователь выбрал больше одной заявки:
        Показать предупреждение "Please select only one application."/"Пожалуйста, выберите только одну заявку."
        Отключить Hire/Принять на работу и Reject/Отклонить.

    Если статус заявки не "New/Новая":
        Отключить Hire/Принять на работу и Reject/Отклонить.

## 3.5 Логика редактирования email/Электронной почты

    HR изменяет email/Электронную почту непосредственно в таблице Applications/Отклики.

    Frontend/Пользовательский интерфейс:
        Сравнивает изменённый email с исходным значением.
        Проверяет, не используется ли такой email другой активной заявкой на ту же должность.
        Активными считаются заявки со статусом "New/Новая" или "Hired/Принят".

    Если обнаружен конфликт:
        Не сохранять изменение.
        Показать предупреждение с конфликтующим email.
        Предоставить возможность скопировать email нажатием.
        Предложить нажать Refresh/Обновить для отмены изменения.

    Если конфликта нет:
        Отправить PATCH-запрос на /api/applications/{app_id}/email.

    Если HTTP 200 OK:
        Сохранить обновлённый email.
        Обновить интерфейс.
        Показать сообщение "Email updated successfully."/"Email успешно обновлён."

    Если HTTP 409 Conflict/Конфликт:
        Показать предупреждение о конфликте email, если ответ указывает на конфликт активной заявки.

    Если HTTP 422 или другая ошибка:
        Показать сообщение об ошибке обновления email.

## 3.6 Логика кнопки "Reject"/"Отклонить"

    Получить email выбранной заявки с учётом редактирования.

    Проверить email на frontend/Пользовательском интерфейсе:
        Если email некорректен:
            Кнопка Reject/Отклонить отключена.

    Если email корректен:
        Отправить PATCH-запрос на /api/applications/{app_id}/status с JSON:
            status/Статус = "Canceled/Отклонена"
            email/Электронная почта  = email кандидата

    Backend/Серверная часть:
        Проверяет, существует ли заявка.
        Проверяет, что текущий статус заявки равен "New/Новая".
        Изменяет статус на "Canceled/Отклонена".
        Сохраняет изменения в базе данных.
        Пытается отправить email кандидату через Gmail SMTP.

    Тема email:
        "Application update"/"Обновление заявки"

    Текст email:
        "Sorry, your application is not a fit for us. Have a good day."

    Если HTTP 200 OK:
        Frontend/Пользовательский интерфейс обновляет интерфейс.
        Показывает сообщение "Application rejected."/"Заявка отклонена."

    Если запрос завершился ошибкой:
        Frontend/Пользовательский интерфейс показывает сообщение об ошибке Reject/Отклонить.

    Важно:
        Если отправка email не удалась, изменение статуса заявки уже может быть сохранено.
        Успешный ответ API не означает, что email обязательно был доставлен.

## 3.7 Логика кнопки "Hire"/"Принять на работу"

    Получить email выбранной заявки с учётом редактирования.
    Получить support_email/Email службы поддержки из поля Support Email/Email службы поддержки.

    Проверить email кандидата:
        Если email некорректен:
            Кнопка Hire/Принять на работу отключена.

    Проверить, что заявка имеет статус "New/Новая".
    Проверить отсутствие конфликта email для выбранной заявки.

    Отправить PATCH-запрос на /api/applications/{app_id}/status с JSON:
        status/Статус        = "Hired/Принят"
        email/Электронная почта         = email кандидата
        support_email/Email службы поддержки = email службы поддержки

    Backend/Серверная часть:
        Проверяет существование заявки.
        Проверяет, что статус заявки равен "New/Новая".
        Находит связанную должность.
        Изменяет статус заявки на "Hired/Принят".
        Устанавливает is_free/Доступна = False/Ложь для связанной должности.
        Сохраняет изменения в базе данных.

    Email кандидату:
        Subject/Тема = "Congratulations! You are hired"
        Message/Сообщение = "Congratulations, you are hired! Come work with us."

    Email службе поддержки (если support_email/Email службы поддержки содержит "@"):
        Subject/Тема = "New employee hired"
        Message/Сообщение = "New employee [full_name/ФИО] hired. Please prepare a workplace."

    Gmail SMTP:
        Использует SMTP_SSL на smtp.gmail.com:465.
        Учетные данные берутся из переменных окружения:
            GMAIL_ADDRESS/Адрес Gmail
            GMAIL_APP_PASSWORD/Пароль приложения Gmail

    Backend/Серверная часть возвращает:
        application_id/ID заявки
        status/Статус
        candidate_email_sent/Email кандидату отправлен
        support_email_sent/Email службе поддержки отправлен (при найме)

    Если отправка email не удалась:
        Backend/Серверная часть записывает ошибку в лог.
        Статус заявки при этом может остаться "Hired/Принят".
        Frontend/Пользовательский интерфейс показывает уведомление об успешном изменении статуса, но это не подтверждает доставку email.

    Если HTTP 200 OK:
        Frontend/Пользовательский интерфейс обновляет интерфейс.
        Показывает сообщение "Application hired."/"Кандидат принят на работу."

    Если запрос завершился ошибкой:
        Frontend/Пользовательский интерфейс показывает сообщение об ошибке Hire/Принять на работу.
